管理**静态**的课程

- 什么是“精选课程”？

课程表：租户id，学导，“教师日程、校区教室可用性与学生可用时间窗|课程基本信息（课程名/科目/级别/总课时/每课时时长/周期与固定上课时间段/上课校区/教室规格/课程容量/候补策略）”UC-SCHED-02

- 课程参与是否放在课程中？否 -> 使用专门的微服务替代，作为关系，这里和用户独立，相关的，“课程容量”和“候补规则”

目前我觉得明确的可以有“用户服务”，但它的服务边界还没有设计好，例如这个应用应该是多租户，而我没有检查租户服务的复杂性，也不好考虑它们是放在一起，还是分别管理。其次，我看到用户在很多不同的功能上会有不同的权限和权限管理需求，我认为它们不应该和用户服务本身放在一起，但它们也需要注意设计。另一个是“课程服务”，但它只负责那些“静态”的课程比如课程信息本身、课程的作业文件等等（如果有），而不去负责那些动态的，例如教师或者学生的排课（特别是它们后续还涉及一些复杂的算法优化）。除此之外，我希望你再为我分析并且整理出来其它的微服务，你可以理解我不希望一个服务规模太大，要尽量职责单一并且解耦。

在有了服务划分后，你可以详细、完整地从文档中提取这个服务的需求细节，把它们列出来，并且对应到文档中的cases，并且设计对应的领域模型，给出相应领域服务的初步简单描述。
