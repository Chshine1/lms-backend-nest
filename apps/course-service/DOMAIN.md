## Domain Model

### 0. Architecture Conventions for Code Generation

The following conventions are mandatory for AI code generation. No implicit assumptions or creative additions are permitted beyond what is explicitly stated in this document.

- **ID Generation & Audit Fields**:
  - All entities have `id: BIGINT` as their primary key, auto-generated by database identity strategy (e.g., PostgreSQL `BIGSERIAL`).
  - All entities that support modification have `createdAt: TIMESTAMPTZ` (immutable, set on creation) and `updatedAt: TIMESTAMPTZ` (auto-updated on any modification).
  - These fields are configured in the ORM entity mapping and do not require manual assignment in domain methods; the ORM framework handles them automatically.
  - Aggregate roots additionally have `version: INTEGER` for optimistic concurrency control, auto-incremented on each save.

- **Domain Events**:
  - Aggregates do not publish events directly. Instead, they record events in an internal collection `_domainEvents: DomainEvent[]`.
  - Aggregate methods invoke event creation and appending (e.g., `this._domainEvents.push(new SomeEvent(...))`) only; the ORM does not handle this.
  - After successful `flush()`, the repository extracts events via `getDomainEvents()`, publishes them to the message broker, then clears them with `clearDomainEvents()`.

- **Uniqueness Validation**:
  - Uniqueness constraints requiring database lookups (e.g., course code, unit name within course) are checked by the Application Service **before** invoking the domain method.
  - Domain methods do not perform I/O; they only validate against in-memory state.

- **External References**:
  - Fields referencing external services (e.g., `teachers: bigint[]`) are stored as raw identifiers.
  - External validation is performed by a Domain Service or Application Service before calling the aggregate method.

- **Collection Mutability**:
  - Arrays and collections do not allow duplicates unless explicitly stated.
  - For scalar collections like `teachers`, adding a duplicate ID results in a no-op.
  - For nested entities (CourseUnit, Attachment), duplicates are prevented by unique constraints or domain rules.

- **Method Side Effects**:
  - Every method description lists side effects: field changes, event recording, exceptions thrown.
  - Side effects are ONLY in-memory; persistence is the responsibility of the repository.

#### Base Schema Inheritance

All entities in this domain extend one of the following base schemas. These base classes provide automatic field management via ORM mappings:

| Base Schema Name      | Inherited Fields                                                                          | Usage                                               |
| :-------------------- | :---------------------------------------------------------------------------------------- | :-------------------------------------------------- |
| `AggregateRootSchema` | `id: BIGINT` (PK), `createdAt: TIMESTAMPTZ`, `updatedAt: TIMESTAMPTZ`, `version: INTEGER` | Used by aggregate roots (`Course`, `Enrollment`)    |
| `EntitySchema`        | `id: BIGINT` (PK), `createdAt: TIMESTAMPTZ`, `updatedAt: TIMESTAMPTZ`                     | Used by child entities (`CourseUnit`, `Attachment`) |

**Important**: Entities extending these schemas do NOT explicitly define the inherited fields in their entity tables (see below). The `extends` row in each entity table references the base schema, and all inherited fields are automatically managed by the ORM framework.

### 3. Aggregate Root Methods: Implementation Patterns

#### 3.1 Course Aggregate Methods

**addUnit(name: string, description: string): void**

Creates a new `CourseUnit` entity with an auto-generated `id` and appends it to the `units` collection. The ORM will assign the `id` when persisting.

```typescript
addUnit(name: string, description: string): void {
  // Validate uniqueness within aggregate
  if (this.units.some(u => u.name === name)) {
    throw new DuplicateUnitNameException(`Unit "${name}" already exists in course`);
  }

  // Create new entity (id will be assigned by ORM on flush)
  const newUnit = new CourseUnit();
  newUnit.name = name;
  newUnit.description = description;
  newUnit.courseId = this.id; // Optional: set relationship

  // Add to collection
  this.units.push(newUnit);

  // Update aggregate timestamp
  this.updatedAt = new Date();
}
```

**updateUnit(unitId: bigint, name?: string, description?: string): void**

Finds the unit by ID and updates specified fields. Validates name uniqueness if changed.

```typescript
updateUnit(unitId: bigint, name?: string, description?: string): void {
  const unit = this.units.find(u => u.id === unitId);
  if (!unit) {
    throw new UnitNotFoundException(`Unit ${unitId} not found`);
  }

  // Validate new name if provided
  if (name !== undefined && name !== unit.name) {
    if (this.units.some(u => u.name === name && u.id !== unitId)) {
      throw new DuplicateUnitNameException(`Unit "${name}" already exists`);
    }
    unit.name = name;
  }

  if (description !== undefined) {
    unit.description = description;
  }

  this.updatedAt = new Date();
}
```

**addAttachmentToUnit(unitId: bigint, attachment: Attachment): void**

Finds the unit and adds an attachment to its collection.

```typescript
addAttachmentToUnit(unitId: bigint, attachment: Attachment): void {
  const unit = this.units.find(u => u.id === unitId);
  if (!unit) {
    throw new UnitNotFoundException(`Unit ${unitId} not found`);
  }

  // Create attachment entity (id will be assigned by ORM)
  const newAttachment = new Attachment();
  newAttachment.fileKey = attachment.fileKey;
  newAttachment.fileName = attachment.fileName;
  newAttachment.sizeBytes = attachment.sizeBytes;
  newAttachment.unitId = unit.id; // Set relationship

  unit.attachments.push(newAttachment);

  this.updatedAt = new Date();
}
```

**removeAttachmentFromUnit(unitId: bigint, fileKey: string): void**

Removes an attachment by fileKey. No-op if not found.

```typescript
removeAttachmentFromUnit(unitId: bigint, fileKey: string): void {
  const unit = this.units.find(u => u.id === unitId);
  if (!unit) {
    throw new UnitNotFoundException(`Unit ${unitId} not found`);
  }

  const index = unit.attachments.findIndex(a => a.fileKey === fileKey);
  if (index >= 0) {
    unit.attachments.splice(index, 1);
    this.updatedAt = new Date();
  }
  // If not found, perform no operation (idempotent)
}
```

**updateMetadata(name?: string, code?: string, description?: string): void**

Updates course metadata fields. Does NOT validate code uniqueness (application service responsibility).

```typescript
updateMetadata(name?: string, code?: string, description?: string): void {
  if (name !== undefined) {
    this.name = name;
  }
  if (code !== undefined) {
    this.code = code;
  }
  if (description !== undefined) {
    this.description = description;
  }

  this.updatedAt = new Date();
}
```

**assignTeacher(teacherId: bigint): void**

Adds teacher ID if not already present. Records domain event.

```typescript
assignTeacher(teacherId: bigint): void {
  if (!this.teachers.includes(teacherId)) {
    this.teachers.push(teacherId);
    this.updatedAt = new Date();

    // Record event for later dispatch by repository
    this._domainEvents.push(
      new TeacherAssignedToCourseEvent({
        courseId: this.id,
        teacherId,
      })
    );
  }
  // If already present, no-op (idempotent)
}
```

#### 3.2 Enrollment Aggregate Methods

**drop(): void**

Transitions status from `ACTIVE` to `DROPPED`. Throws if already dropped or completed.

```typescript
drop(): void {
  if (this.status !== EnrollmentStatus.ACTIVE) {
    throw new InvalidEnrollmentStateException(
      `Cannot drop enrollment with status ${this.status}`
    );
  }
  this.status = EnrollmentStatus.DROPPED;
  this.updatedAt = new Date();
}
```

**complete(): void**

Transitions status from `ACTIVE` to `COMPLETED`. Throws if already dropped or completed.

```typescript
complete(): void {
  if (this.status !== EnrollmentStatus.ACTIVE) {
    throw new InvalidEnrollmentStateException(
      `Cannot complete enrollment with status ${this.status}`
    );
  }
  this.status = EnrollmentStatus.COMPLETED;
  this.updatedAt = new Date();
}
```

### 4. Domain Events and Dispatching Pattern

**Event Recording and Dispatching Pattern**:

1. **Event Recording**: Each aggregate root maintains a protected `_domainEvents: DomainEvent[] = []` collection. When a domain method produces a significant business event, it creates an immutable event object and appends it to this internal collection.

2. **Event Publishing**: After the repository persists an aggregate via `flush()`, it is responsible for:
   - Extracting recorded events via `aggregate.getDomainEvents()` (returns a copy)
   - Publishing each event to the configured message broker (Kafka/RabbitMQ)
   - Calling `aggregate.clearDomainEvents()` to reset the list and prevent re-publishing

3. **Aggregate Methods**: All aggregates provide:
   - `protected _domainEvents: DomainEvent[] = []` – internal event storage
   - `getDomainEvents(): DomainEvent[]` – returns a shallow copy of all recorded events
   - `clearDomainEvents(): void` – clears the internal event list

**Implementation Example (MikroORM)**:

```typescript
// Domain: Course Aggregate
export class Course extends AggregateRootSchema {
  protected _domainEvents: DomainEvent[] = [];

  assignTeacher(teacherId: bigint): void {
    if (!this.teachers.includes(teacherId)) {
      this.teachers.push(teacherId);
      this.updatedAt = new Date();

      // Record event for later dispatch
      this._domainEvents.push(
        new TeacherAssignedToCourseEvent({
          courseId: this.id,
          teacherId,
        }),
      );
    }
  }

  getDomainEvents(): DomainEvent[] {
    return [...this._domainEvents];
  }

  clearDomainEvents(): void {
    this._domainEvents = [];
  }
}

// Repository: Event Dispatching Logic
export class CourseRepository implements ICourseRepository {
  constructor(
    private em: EntityManager,
    private eventBus: EventBusService,
  ) {}

  async save(course: Course): Promise<void> {
    // Persist the aggregate
    this.em.persist(course);
    await this.em.flush(); // ← Events published AFTER flush() completes

    // Extract and dispatch events
    const events = course.getDomainEvents();
    for (const event of events) {
      await this.eventBus.publish(event);
    }

    // Prevent re-publishing on subsequent saves
    course.clearDomainEvents();
  }
}
```

| Event Name                       | Payload Data                             | Triggering Point                                                                                                                           |
| :------------------------------- | :--------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **CourseCreatedEvent**           | `courseId`, `name`, `code`, `teacherIds` | Recorded by `CourseApplicationService.createCourse` during creation of a new Course aggregate (factory operation, not an instance method). |
| **StudentEnrolledEvent**         | `enrollmentId`, `studentId`, `courseId`  | Recorded by `Enrollment` aggregate constructor upon instantiation.                                                                         |

### 7. Key Business Rules & Invariants

| Rule ID   | Description                                                                 | Enforcement Location                                                              |
| :-------- | :-------------------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| **BR-01** | Course code must be unique across the system.                               | Database `UNIQUE` constraint and Application Service pre-check before save.       |
| **BR-02** | A student cannot have more than one `ACTIVE` enrollment in the same course. | Database `UNIQUE(studentId, courseId)` constraint and `EnrollmentDomainService`.  |
| **BR-03** | A course unit name must be unique within its parent course.                 | `Course.addUnit` and `Course.updateUnit` methods.                                 |
| **BR-04** | Archived courses cannot accept new enrollments.                             | `EnrollmentApplicationService` checks course `status` before allowing enrollment. |
| **BR-05** | A student may only be enrolled once per course with status `ACTIVE`.        | `EnrollmentDomainService.enroll` enforces via `EnrollmentRepository` queries.     |

### 8. Repository Interfaces

**CourseRepository** handles persistence of `Course` aggregates with their nested `CourseUnit` and `Attachment` collections:

```typescript
interface ICourseRepository {
  /**
   * Persists a Course aggregate and dispatches domain events after flush.
   * The repository extracts events via getDomainEvents(), publishes them,
   * then calls clearDomainEvents() to prevent re-publishing.
   */
  save(course: Course): Promise<void>;

  /**
   * Retrieves a Course by ID. By default, does not load nested collections.
   * Pass { include: ['courseUnits'] } or equivalent to load related units,
   * or { include: ['courseUnits.attachments'] } for full depth.
   */
  findById(
    id: bigint,
    options?: { include?: string[] },
  ): Promise<Course | null>;

  /**
   * Retrieves a Course by its unique code.
   */
  findByCode(code: string): Promise<Course | null>;
}

interface IEnrollmentRepository {
  /**
   * Persists an Enrollment aggregate and dispatches domain events after flush.
   */
  save(enrollment: Enrollment): Promise<void>;

  /**
   * Retrieves an enrollment by student and course (unique pair).
   */
  findByStudentAndCourse(
    studentId: bigint,
    courseId: bigint,
  ): Promise<Enrollment | null>;

  /**
   * Retrieves all active enrollments for a student.
   */
  findActiveByStudent(studentId: bigint): Promise<Enrollment[]>;

  /**
   * Retrieves an enrollment by its ID.
   */
  findById(id: bigint): Promise<Enrollment | null>;
}
```

**Implementation Example (MikroORM Pattern)**:

```typescript
export class CourseRepository implements ICourseRepository {
  constructor(private em: EntityManager) {}

  async save(course: Course): Promise<void> {
    this.em.persist(course);
    await this.em.flush(); // ← Must flush BEFORE event dispatch

    // Extract events recorded during domain operations
    const events = course.getDomainEvents();
    for (const event of events) {
      await this.eventBus.publish(event);
    }
    course.clearDomainEvents();
  }

  async findById(
    id: bigint,
    options?: { include?: string[] },
  ): Promise<Course | null> {
    // Example: { include: ['courseUnits', 'courseUnits.attachments'] }
    // MikroORM: populate(options?.include ?? [])
    return await this.em.findOne(
      Course,
      { id },
      {
        populate: options?.include ?? [],
      },
    );
  }

  async findByCode(code: string): Promise<Course | null> {
    return await this.em.findOne(Course, { code });
  }
}
```

### 12. Microservice Integration Note

- `User` data resides in a separate `user-service`. User ID validation is performed by `UserServiceClient` (interface) in `EnrollmentDomainService`.
- This service publishes domain events to a message broker (Kafka/RabbitMQ) via the repository dispatch mechanism after `flush()`.
- `assessment-service` subscribes to `StudentEnrolledEvent` and creates a local read-model so it can answer: "Is Student X allowed to view/submit to Assignment Y?" without synchronous calls to `course-service`.
- `FileStorage` (S3/MinIO) integration: `StorageService` interface handles uploads; generated `fileKey` is stored in `Attachment` entity.

### 13. Aggregate Root Relationship Loading (ORM Pattern)

**MikroORM Relationship Management**:

When loading a `Course` aggregate from the repository, nested entities (`CourseUnit`, `Attachment`) are not loaded by default (lazy loading disabled). Use explicit `include()` or `populate()` options to load specific relationships:

```typescript
// Load course without units
const course = await courseRepository.findById(courseId);
// course.courseUnits === [] (empty, not loaded)

// Load course WITH units
const course = await courseRepository.findById(courseId, {
  include: ['courseUnits'],
});
// course.courseUnits is now populated

// Load course WITH units AND attachments
const course = await courseRepository.findById(courseId, {
  include: ['courseUnits', 'courseUnits.attachments'],
});
// course.courseUnits[0].attachments is populated

// Domain operations on nested entities
course.addUnit('Module 1', 'Description');
course.courseUnits[0].addAttachment(newAttachment);

// Persist the entire aggregate tree
await courseRepository.save(course);
// All changes (new units, modified units, new attachments) are persisted in one transaction
```

This pattern ensures:

- **Performance**: Relationships are only loaded when needed
- **Consistency**: The aggregate root controls access to nested entities
- **Simplicity**: All changes are persisted together with a single `save()` call
